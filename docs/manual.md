# x-post-scheduler 操作マニュアル

Markdown 形式の投稿スケジュールを X (Twitter) の予約投稿に一括登録するツールです。  
ChatGPT や Claude で生成した投稿スケジュールをそのまま読み込んで、自動で X に予約投稿できます。

## 1. 動作環境

| 項目 | 要件 |
|------|------|
| OS | Windows 10/11、macOS、Linux |
| Node.js | バージョン 18 以上 |
| ブラウザ | Google Chrome（インストール済みであること） |
| ネットワーク | インターネット接続が必要 |

**Node.js のインストール（まだの場合）**

https://nodejs.org/ にアクセスし、「LTS」バージョンをダウンロードしてインストールしてください。

## 2. セットアップ（初回のみ）

### Windows の場合

1. ZIP ファイルを任意の場所に展開します
2. 展開したフォルダ内の **`scripts\setup.bat`** をダブルクリックします
3. 自動で依存パッケージがインストールされます
4. `config.json` が自動生成されます（必要に応じて編集してください）

### Mac / Linux の場合

```bash
cd x-post-scheduler-v1.0.0
chmod +x scripts/*.sh
./scripts/setup.sh
```

### セットアップ後のフォルダ構成

```
x-post-scheduler-v1.0.0/
├── scripts/
│   ├── setup.bat / setup.sh       ← セットアップ（初回のみ）
│   ├── login.bat / login.sh       ← X ログイン
│   ├── server.bat / server.sh     ← Web UI 起動
│   └── schedule.bat / schedule.sh ← CLI 一括予約
├── dist/                          ← プログラム本体（変更不要）
├── vendor/                        ← 同梱ライブラリ（変更不要）
├── node_modules/                  ← セットアップ後に自動生成
├── config.json                    ← 設定ファイル（編集可能）
├── config.example.json            ← 設定ファイルのテンプレート
└── manual.md                      ← このファイル
```

## 3. X にログイン

予約投稿を行うには、最初に X のアカウントにログインする必要があります。  
**セッションが切れた場合も、同じ手順で再ログインしてください。**

### 手順

1. **`scripts\login.bat`** をダブルクリック（Mac/Linux: `./scripts/login.sh`）
2. Google Chrome が起動し、X のログインページが開きます
3. 通常通り X にログインしてください（2段階認証にも対応しています）
4. ログインが完了したら、**ブラウザを閉じて**ください（×ボタン）
5. ターミナルに「ログイン完了」と表示されれば完了です

### 注意事項

- ログインには通常の Chrome が起動します。X のボット検知に引っかかりにくい方式です
- セッション情報は `.session/` フォルダに保存されます（このフォルダは他人に共有しないでください）
- ログイン後にブラウザを手動で閉じないとセッションが保存されません

## 4. Web UI の使い方

Web UI を使うと、ブラウザ上で投稿の確認・編集・予約実行をまとめて行えます。  
**初めてお使いの方は、こちらの方法を推奨します。**

### 4.1 サーバーを起動する

1. **`scripts\server.bat`** をダブルクリック（Mac/Linux: `./scripts/server.sh`）
2. ターミナルに「Web UI: http://localhost:3456」と表示されます
3. ブラウザで **http://localhost:3456** を開きます

停止するには、ターミナルで `Ctrl+C` を押してください。

### 4.2 画面の構成

```
┌─────────────────────────────────────────────┐
│ x-post-scheduler            🟢 セッション有効 │  ← ヘッダー（セッション状態）
├─────────────────────────────────────────────┤
│ ┌─────────────────────────────────────────┐ │
│ │  Markdown をここに貼り付け              │ │  ← 入力エリア
│ └─────────────────────────────────────────┘ │
│  [ファイルを選択]              [読み込み]    │
├─────────────────────────────────────────────┤
│  合計: 5件  画像付き: 2件  エラー: 0件      │  ← サマリーバー
├─────────────────────────────────────────────┤
│ ┌──────────────────────────┐               │
│ │ 📅 2026/03/27 09:00      │  ← 投稿カード │
│ │ おはようございます！      │               │
│ │ [画像サムネイル]          │               │
│ │ ステータス: 未予約  140文字│               │
│ └──────────────────────────┘               │
│  ...（投稿カードが続く）                    │
├─────────────────────────────────────────────┤
│         [ドライラン]  [一括予約実行]         │  ← 実行ボタン
└─────────────────────────────────────────────┘
```

### 4.3 基本的な流れ

#### Step 1: Markdown を読み込む

以下のいずれかの方法で Markdown を入力します：

- **貼り付け**: テキストエリアに直接 Markdown を貼り付ける
- **ファイル選択**: 「ファイルを選択」ボタンで `.md` ファイルを選ぶ
- **ドラッグ＆ドロップ**: Markdown ファイルをテキストエリアにドロップ

「**読み込み**」ボタンをクリックすると、投稿カードが時系列順に表示されます。

#### Step 2: 投稿内容を確認・編集する

各投稿カードで以下の操作ができます：

| 操作 | 方法 |
|------|------|
| 本文を編集 | テキスト部分をクリックして直接編集 |
| 日時を変更 | 日時部分をクリック |
| 投稿を削除 | カード右上の ✕ ボタン |
| 文字数を確認 | カード下部にリアルタイム表示（140文字制限・URLは10文字換算） |

#### Step 3: 画像を管理する

各投稿カードで画像の追加・管理ができます：

- **URL で追加**: 画像 URL を入力して追加（サーバー側で自動ダウンロード）
- **ファイルで追加**: ローカルの画像ファイルをアップロード
- **並び替え**: ドラッグ＆ドロップで画像の順番を変更
- **削除**: サムネイル上の ✕ ボタン

> 画像は1投稿あたり **最大4枚** まで添付できます。

#### Step 4: 予約を実行する

1. まず **「ドライラン」** で動作確認することを推奨します
   - X の投稿作成画面を開いてテキスト入力・日時設定まで行いますが、最終的な予約ボタンは押しません
2. 問題なければ **「一括予約実行」** をクリック
3. Chrome が起動し、順番に予約が実行されます
4. 各投稿カードのステータスがリアルタイムで更新されます
5. 完了後に成功/失敗件数が表示されます

#### 失敗した投稿をリトライする

失敗した投稿カードに「**リトライ**」ボタンが表示されます。クリックするとその投稿のみ再実行されます。

### 4.4 セッション状態の見方

画面右上にセッションの状態が表示されます：

| 表示 | 意味 | 対処 |
|------|------|------|
| 🟢 セッション有効 | ログイン済み。予約実行可能 | — |
| 🔴 セッションなし | ログインが必要 | `login.bat` を実行 |
| 🔴 セッション切れ | 再ログインが必要 | `login.bat` を実行 |

## 5. CLI の使い方

Web UI を使わず、コマンドラインから直接予約実行することもできます。

### 一括予約

```bash
# Windows
scripts\schedule.bat スケジュール.md

# Mac/Linux
./scripts/schedule.sh スケジュール.md
```

### オプション

| オプション | 説明 | 例 |
|-----------|------|-----|
| `--dry-run` | 予約ボタンを押さずに確認のみ | `schedule.bat file.md --dry-run` |
| `--headless` | ブラウザを表示しない | `schedule.bat file.md --headless` |
| `--delay <ms>` | 投稿間の待機時間（ミリ秒） | `schedule.bat file.md --delay 8000` |
| `--config <path>` | 設定ファイルを指定 | `schedule.bat file.md --config my-config.json` |

### CLI 実行時の流れ

```
1. Markdown ファイルを読み込んでパース
2. バリデーション（文字数・日時の確認）
3. 投稿一覧をプレビュー表示
4. セッション確認
5. 順次予約実行（進捗表示あり）
6. 完了サマリー表示（成功/失敗件数）
```

## 6. Markdown の書き方

ChatGPT や Claude に投稿スケジュールを生成してもらう際、以下の3形式のいずれかで出力してもらうと自動認識されます。

### 形式A: テーブル形式（推奨）

```markdown
| 日時 | 投稿内容 | 画像URL |
|------|----------|---------|
| 2026-03-27 09:00 | おはようございます！今日も素敵な一日を | https://example.com/morning.jpg |
| 2026-03-27 12:00 | ランチタイムにおすすめの一品 | |
| 2026-03-27 18:00 | 今日の振り返り #日記 | https://example.com/evening.jpg |
```

- ヘッダー行は日本語・英語どちらでも認識されます
  - 日時列: `日時`、`日付`、`date`、`datetime`
  - 本文列: `投稿内容`、`内容`、`テキスト`、`本文`、`text`、`content`
  - 画像列: `画像`、`画像URL`、`image`（省略可）

### 形式B: リスト形式

```markdown
- **2026-03-27 09:00**
  おはようございます！今日も素敵な一日を
  画像: https://example.com/morning.jpg

- **2026-03-27 12:00**
  ランチタイムにおすすめの一品

- **2026-03-27 18:00**
  今日の振り返り #日記
```

- 日時は太字（`**...**`）で囲んでください
- 本文は次の行にインデント付きで記述
- 画像は `画像: URL` の形式で指定

### 形式C: 見出し+本文形式

```markdown
## 2026-03-27 09:00

おはようございます！今日も素敵な一日を

![朝の風景](https://example.com/morning.jpg)

## 2026-03-27 12:00

ランチタイムにおすすめの一品
```

- `##` 見出しに日時を記述
- 本文はその下に通常テキストとして記述
- 画像は Markdown 画像記法 `![代替テキスト](URL)` で指定

### 日時のフォーマット

| 形式 | 例 | 備考 |
|------|-----|------|
| `YYYY-MM-DD HH:mm` | `2026-03-27 09:00` | 推奨 |
| `YYYY/MM/DD HH:mm` | `2026/03/27 09:00` | スラッシュ区切り |
| `MM/DD HH:mm` | `03/27 09:00` | 年省略（当年として扱います） |

> 時刻はすべて日本時間（Asia/Tokyo）として解釈されます。

### 画像の指定方法

| 方法 | 書き方 |
|------|--------|
| Markdown 画像記法 | `![代替テキスト](https://example.com/img.jpg)` |
| 画像ラベル | `画像: https://example.com/img.jpg` |
| 裸の画像 URL | `https://example.com/img.jpg`（行頭に単独で記載） |

対応形式: `.jpg`、`.jpeg`、`.png`、`.gif`、`.webp`（1投稿あたり最大4枚）

### AI への指示例

```
来週の月〜金の投稿スケジュールを作成してください。
以下の形式で出力してください。

| 日時 | 投稿内容 |
|------|----------|
| YYYY-MM-DD HH:mm | 投稿テキスト |

条件:
- 1日2回（9:00 と 18:00）
- テーマ: 商品紹介
- 140文字以内
- ハッシュタグを2〜3個含める
```

## 7. 設定ファイル

`config.json` で動作をカスタマイズできます。セットアップ時に `config.example.json` から自動生成されます。

```json
{
  "sessionDir": "./.session",
  "headless": false,
  "delayBetweenPosts": 5000,
  "timezone": "Asia/Tokyo"
}
```

| 項目 | 説明 | デフォルト値 |
|------|------|-------------|
| `sessionDir` | ログインセッションの保存先 | `./.session` |
| `headless` | ブラウザを非表示で実行するか | `false` |
| `delayBetweenPosts` | 投稿間の待機時間（ミリ秒） | `5000` |
| `timezone` | タイムゾーン | `Asia/Tokyo` |

**`headless` について**
- `false`（デフォルト）: ブラウザが表示されます。初回や動作確認時はこちらを推奨します
- `true`: ブラウザが表示されません。安定動作を確認した後の自動運用向けです

**`delayBetweenPosts` について**
- 5000（5秒）未満に設定すると、X のレート制限に引っかかる可能性があります

## 8. トラブルシューティング

### セットアップ時

#### 「Node.js がインストールされていません」と表示される

https://nodejs.org/ から Node.js をインストールしてください。  
インストール後、ターミナルを再起動してから `setup.bat` を再実行してください。

#### `npm install` に失敗する

- インターネット接続を確認してください
- プロキシ環境の場合は npm のプロキシ設定が必要です:
  ```bash
  npm config set proxy http://proxy.example.com:8080
  npm config set https-proxy http://proxy.example.com:8080
  ```

### ログイン時

#### Chrome が起動しない

Google Chrome がインストールされているか確認してください。  
デフォルトのインストール先（`C:\Program Files\Google\Chrome`）にない場合、検出に失敗することがあります。

#### ログインしたのに「セッションなし」になる

ログイン後、必ずブラウザを **×ボタンで手動で閉じて**ください。  
ブラウザがクラッシュした場合はセッションが保存されません。再度 `login.bat` を実行してください。

### 予約実行時

#### 「セッション切れ」と表示される

X のセッションが期限切れです。再度 `login.bat` を実行してログインし直してください。

#### 特定の投稿だけ失敗する

考えられる原因：

| 原因 | 対処 |
|------|------|
| 文字数が140文字を超えている | Web UI の文字数カウンターを確認して編集 |
| 日時が過去になっている | 日時を修正する（X は過去日時を受け付けない） |
| ネットワーク遅延 | `delayBetweenPosts` を `8000` 以上に増やす |
| X の UI 変更 | ツールのアップデートを確認してください |

Web UI では失敗した投稿を「**リトライ**」ボタンで個別に再実行できます。

#### 日時ピッカーの操作がうまくいかない

Chrome の言語設定を日本語または英語に設定してください。

### Web UI

#### http://localhost:3456 にアクセスできない

- `server.bat` が実行中であることを確認してください
- 別のアプリが同じポートを使用している場合は、別ポートで起動できます:
  ```bash
  node dist/index.js server --port 8080
  ```

#### 画像が表示されない

- 画像 URL が有効かブラウザで直接アクセスして確認してください
- ローカルファイルの場合は、Web UI のファイルアップロード機能を使ってください
